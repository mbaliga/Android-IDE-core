# Trademarks

This repository's **code** is licensed under Apache-2.0 (see `LICENSE`). Apache-2.0 §6 is explicit
that the code license does not grant any trademark rights — this file states this project's
trademark policy separately, following the pattern used by Mozilla/Firefox and the Linux
Foundation's member projects.

**⚠ Status note (2026-08-01):** the project's consumer-facing brand name is, as of this writing,
**unresolved between three candidates** — "FoneBru" (ruled as decision S3 in the private
`Android-IDE-Studio` repo's `docs/STUDIO_SUITE_BRIEF.md`, 2026-07-11), "Fonebrew," and
"Phonebrew"/"fonebru" (informally recorded elsewhere). This file is written to hold regardless of
which name is finally settled on — it governs **the name that ships**, whichever that turns out to
be, plus the identifiers below that are already fixed in code and unaffected by that choice.

## What's covered

- **"Aarso"** — the project's `rootProject.name`, its `dev.aarso` package/application-id root, and
  the name of the private self-reflection lens (`Aarso`, package `dev.aarso.domain.mirror`) are
  Madhav Baliga's marks.
- **Whichever consumer-facing brand name is finally ruled** (see the status note above) and any
  associated logos, wordmarks, or icon assets, once they exist — these are Madhav Baliga's marks,
  not licensed under Apache-2.0.
- Logo/icon/brand-asset files, wherever they're added to this repo, are covered by a separate
  all-rights-reserved (or CC-BY-ND, once chosen) notice placed alongside those files — never the
  Apache-2.0 code license. No such asset files exist in this repo as of this writing.

## What you may do

- **Build and distribute unmodified official releases** of this project, under the project's own
  name, including through F-Droid or other unmodified-build distribution channels. This does not
  require separate trademark permission.
- **Fork, modify, and redistribute the code** — Apache-2.0 already grants this. You do not need
  trademark permission to fork.
- **Refer to this project by name** in truthful, non-confusing statements (e.g. "based on
  Aarso/[brand]," "a fork of Aarso/[brand]") with a clear no-affiliation disclaimer where relevant.

## What you may not do

- **Ship a modified build under the project's name or brand**, or in a way that could confuse users
  into thinking a modified build is the official one. Forks must pick their own name.
- **Use the `dev.aarso.*` application ID namespace** for a modified/forked build. Pick your own
  application ID.
- **Use the project's logo, icon, or wordmark as your own app's branding**, once such assets exist,
  without separate permission.

## Enforcement posture

Informal first: a polite request to rename/re-brand. If that doesn't resolve it, a trademark
complaint to the relevant repo host or app store, in that order — consistent with how most
open-source projects with a protected name handle this (see e.g. Mozilla's trademark policy).

## Contact

Trademark questions: open an issue on this repository, or reach the maintainer through the contact
information on the project's own listing/website once one is live.
